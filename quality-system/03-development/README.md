# 开发构建

全局自动化质量流程图见：[README.md](../README.md)

## 环节目标

高质量地实现设计意图。开发构建包含单元测试——验证前置，测试是开发的一部分。

## 验证动作

本环节所有验证动作由 CI/CD 流水线自动触发，除代码审查外全部自动化。

| # | 动作 | 执行者 | 触发时机 | 自动化 |
|---|------|--------|---------|--------|
| 1 | 单元测试 | CI 自动 | 每次提交 | **自动** |
| 2 | 增量 SAST（静态分析） | CI 自动 | 每次提交 | **自动** |
| 3 | 增量 SCA（依赖安全扫描） | CI 自动 | 依赖变更时 | **自动** |
| 4 | 代码审查 | 开发者互审 | 合并前 | **手动** |
| 5 | CI 构建 | CI 自动 | 每次提交 | **自动** |

## 质量门禁

进入下一环节（质量确认）前，须满足：

- [ ] 代码审查（Code Review）通过
- [ ] 单元测试覆盖率达到目标值（≥ 80%）
- [ ] 增量 SAST 无高危问题
- [ ] CI 构建通过

## 安全要求

- 增量 SCA 无高危已知漏洞
- 安全编码规范遵守
- 无已知高危依赖漏洞

## 关联原则

- **原则一：质量是全团队的责任** — 每位开发者对代码质量负责
- **原则五：验证前置** — 单元测试是开发者的第一道验证
- **原则六：安全是默认属性** — 安全编码从开发阶段开始

## 度量指标

| 指标 | 目标值 |
|------|--------|
| 单元测试覆盖率 | ≥ 80% |
| 代码审查覆盖率 | 100% |
| 增量 SAST 高危问题 | = 0 |
| 构建失败率 | ≤ 5% |
