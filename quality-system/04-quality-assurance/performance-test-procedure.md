# 性能测试规程

## 目的

验证系统在预期负载下的性能表现，确保满足性能需求和质量属性要求。

## 适用范围

- 版本发布前的性能验证
- 性能敏感功能变更后的性能验证
- 系统容量规划和瓶颈分析

## 职责

| 角色 | 职责 |
|------|------|
| 质量工程师 | 制定性能测试计划、编写和执行性能测试 |
| 开发者 | 配合定位性能瓶颈、实施性能优化 |
| 技术负责人 | 审批性能测试计划、确认性能指标 |

## 性能指标

| 指标 | 定义 | 说明 |
|------|------|------|
| 响应时间（Response Time） | 请求发出到收到完整响应的时间 | 关注 P50、P95、P99 |
| 吞吐量（Throughput） | 单位时间内处理的请求数 | RPS（Requests Per Second） |
| 错误率（Error Rate） | 失败请求占总请求的比例 | ≤ 1% 为达标 |
| 并发用户数（Concurrency） | 系统同时服务的用户数 | 需区分在线用户和活跃用户 |
| 资源利用率（Resource Utilization） | CPU、内存、磁盘 IO、网络 IO | ≤ 80% 为安全水位 |

## 测试类型

### 负载测试（Load Testing）

验证系统在预期负载下的表现。

- 目标：确认系统在正常负载下性能指标达标
- 负载：预期峰值负载的 100%
- 持续时间：≥ 15 分钟

### 压力测试（Stress Testing）

验证系统在超出预期负载时的表现和恢复能力。

- 目标：找到系统性能拐点和最大承载能力
- 负载：逐步增加到系统出现明显降级
- 持续时间：≥ 10 分钟

### 稳定性测试（Endurance Testing）

验证系统在长时间运行下的稳定性。

- 目标：发现内存泄漏、资源耗尽等长时间运行问题
- 负载：正常负载的 70%-80%
- 持续时间：≥ 2 小时（关键系统 ≥ 8 小时）

### 峰值测试（Spike Testing）

验证系统在突发流量下的表现。

- 目标：确认系统能应对突发流量并恢复
- 负载：瞬间增加到峰值负载的 200%
- 持续时间：突发持续 1-5 分钟，观察恢复

## 流程

### 1. 制定性能测试计划

- 确定测试目标和性能指标基线
- 识别关键业务场景（与生产流量分布一致）
- 定义负载模型（并发用户数、请求分布）
- 准备测试数据

### 2. 编写测试脚本

- 基于关键业务场景编写
- 模拟真实用户行为（思考时间、操作间隔）
- 参数化测试数据
- 添加断言（响应时间、状态码、业务结果）

### 3. 执行测试

- 在类生产环境执行
- 先执行负载测试，再执行压力测试
- 监控系统资源指标
- 记录测试过程和结果

### 4. 分析结果

- 对比性能指标与基线
- 识别性能瓶颈
- 分析资源利用率和错误率
- 输出性能测试报告

### 5. 优化验证

- 对性能不达标的场景进行优化
- 优化后重新执行测试验证
- 直到性能指标达标

## 测试报告

性能测试报告包含：

1. **测试概述**：目标、环境、负载模型
2. **测试结果**：各指标数据、对比基线
3. **瓶颈分析**：识别的瓶颈和原因
4. **优化建议**：改进措施和优先级
5. **结论**：是否满足发布条件

## 度量

| 指标 | 目标值 |
|------|--------|
| 核心接口 P95 响应时间 | ≤ 500ms |
| 页面加载 P95 响应时间 | ≤ 2s |
| 峰值负载错误率 | ≤ 1% |
| 资源利用率安全水位 | ≤ 80% |
