# 安全测试规程

## 目的

识别和验证系统中的安全漏洞，确保产品在发布前满足安全要求。

## 适用范围

- 每次版本发布前的安全验证
- 安全敏感功能变更后的专项测试
- 定期安全扫描

## 职责

| 角色 | 职责 |
|------|------|
| 质量工程师 | 执行 SAST/DAST 扫描、编写安全测试用例 |
| 安全负责人 | 审批安全测试计划、评估漏洞风险 |
| 开发者 | 修复安全漏洞、配合安全测试 |

## 安全测试类型

### SAST（静态应用安全测试）

- **工具**：SonarQube / Semgrep / Snyk Code
- **执行时机**：每次代码提交（CI 集成）
- **扫描范围**：全部源代码
- **关注点**：
  - SQL 注入
  - XSS（跨站脚本）
  - 硬编码密钥和凭证
  - 不安全的反序列化
  - 路径遍历

### DAST（动态应用安全测试）

- **工具**：OWASP ZAP / Burp Suite
- **执行时机**：发布前、重大功能变更后
- **扫描范围**：运行中的应用
- **关注点**：
  - 认证和会话管理漏洞
  - 授权绕过
  - 敏感数据暴露
  - CSRF（跨站请求伪造）
  - 不安全的 HTTP 头

### SCA（软件成分分析）

- **工具**：Snyk / Dependabot / OWASP Dependency-Check
- **执行时机**：每次依赖变更（CI 集成）
- **扫描范围**：第三方依赖
- **关注点**：
  - 已知漏洞（CVE）
  - 过时依赖
  - 许可证合规

### 渗透测试

- **执行方**：外部安全团队或专业安全工程师
- **执行时机**：重大版本发布前、年度安全审计
- **范围**：完整应用系统
- **关注点**：
  - 业务逻辑漏洞
  - 权限提升
  - 数据泄露路径

## 漏洞等级

| 等级 | CVSS 评分 | 修复时效 | 示例 |
|------|----------|---------|------|
| 高危 | ≥ 7.0 | ≤ 24 小时 | SQL 注入、未授权数据访问 |
| 中危 | 4.0 - 6.9 | ≤ 7 天 | 存储型 XSS、不安全的直接对象引用 |
| 低危 | < 4.0 | ≤ 30 天 | 信息泄露、不安全的 HTTP 头 |

## 流程

### 1. 安全测试计划

- 确定测试范围和类型
- 识别安全敏感功能
- 定义测试环境
- 安排测试时间

### 2. 执行安全扫描

- SAST：CI 自动执行，阻断高危问题
- SCA：CI 自动执行，阻断高危依赖
- DAST：在 Staging 环境执行
- 渗透测试：按计划执行

### 3. 漏洞评估

- 对发现的漏洞进行等级评定
- 评估业务影响
- 确定修复优先级
- 记录到缺陷管理系统

### 4. 漏洞修复

- 按修复时效要求完成修复
- 修复方案需经安全负责人审查
- 高危漏洞修复需专项验证

### 5. 回归验证

- 修复后重新执行相关安全测试
- 确认漏洞已修复且未引入新问题
- 验证通过后关闭缺陷

### 6. 安全测试报告

报告包含：

1. 测试范围和方法
2. 发现的漏洞清单（等级、描述、影响）
3. 修复状态
4. 残留风险评估
5. 发布建议

## 发布安全门禁

发布前须满足：

- [ ] SAST 扫描无高危问题
- [ ] SCA 无高危已知漏洞
- [ ] DAST 扫描完成，高危漏洞已修复
- [ ] 安全测试报告已审批

## 安全合规要求

教育行业产品须特别关注：

- **个人信息保护法**：学生数据收集、存储、使用的合规性
- **数据安全法**：教育数据的分类分级和安全管理
- **未成年人保护**：未成年人信息的特殊保护措施

## 度量

| 指标 | 目标值 |
|------|--------|
| 高危漏洞修复时效 | ≤ 24 小时，达标率 100% |
| 中危漏洞修复时效 | ≤ 7 天，达标率 100% |
| 发布时高危漏洞数 | = 0 |
| 安全测试覆盖率 | 核心功能 100% |
