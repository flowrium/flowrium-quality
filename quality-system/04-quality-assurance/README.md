# 质量确认

## 环节目标

制定全流程测试策略，执行集成级及以上验证，确认质量门禁达标。

质量确认环节不执行单元测试（单元测试属于开发构建环节），但**测试策略由本环节统一制定**——包括各层级的覆盖要求和责任归属。

## 质量门禁

进入下一环节（发布交付）前，须满足：

- [ ] 测试计划执行完毕
- [ ] 严重缺陷（P0/P1）清零
- [ ] 验收测试通过
- [ ] 安全测试执行完毕，高危漏洞修复验证通过
- [ ] 质量门禁确认清单通过

## 安全要求

- 安全测试（SAST/DAST）执行
- 漏洞修复验证
- 安全回归测试通过

## 关联原则

- **原则五：验证前置** — 在发布前确认所有质量门禁达标
- **原则六：安全是默认属性** — 安全测试是质量确认的必要组成部分

## 度量指标

| 指标 | 目标值 |
|------|--------|
| 测试用例通过率 | ≥ 98% |
| 严重缺陷清零（发布时 P0/P1） | = 0 |
| 缺陷修复时效（P0≤4h/P1≤24h/P2≤72h） | 达标率 ≥ 95% |
| 缺陷逃逸率 | ≤ 10% |
| 自动化测试占比 | ≥ 60% |
| 安全漏洞修复时效（高危≤24h/中危≤7d） | 达标率 100% |
