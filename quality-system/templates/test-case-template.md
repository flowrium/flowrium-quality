# 测试用例模板

## 模板说明

本模板定义测试用例的标准格式，所有测试用例（手工和自动化）均须遵循。

## 用例结构

### 基本信息

| 字段 | 说明 |
|------|------|
| 用例编号 | 唯一标识，格式：`TC-{模块}-{序号}`，如 `TC-AUTH-001` |
| 用例标题 | 简明描述测试目的，如"用户使用正确密码登录成功" |
| 优先级 | P0 / P1 / P2 |
| 所属模块 | 功能模块名称 |
| 关联需求 | 需求编号或用户故事编号 |
| 测试类型 | 功能 / 性能 / 安全 / 兼容性 |
| 自动化状态 | 已自动化 / 待自动化 / 不适合自动化 |

### 前置条件

列出执行本用例前必须满足的条件：

- 系统状态（如：用户已注册、数据已初始化）
- 环境要求（如：特定浏览器版本、网络条件）
- 数据准备（如：测试账号、测试数据）

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 描述用户操作 | 描述系统应返回的响应或状态变化 |
| 2 | ... | ... |

### 预期结果

- 主预期结果：测试步骤最后一步的预期
- 附加验证点：操作过程中的中间状态验证（如：数据库记录、日志输出、界面状态）

### 后置清理

- 测试数据清理方式
- 系统状态恢复方式

## 示例

### 基本信息

| 字段 | 值 |
|------|-----|
| 用例编号 | TC-AUTH-001 |
| 用例标题 | 用户使用正确密码登录成功 |
| 优先级 | P0 |
| 所属模块 | 认证模块 |
| 关联需求 | US-001 用户登录 |
| 测试类型 | 功能 |
| 自动化状态 | 已自动化 |

### 前置条件

- 用户已注册，账号：testuser@example.com，密码：ValidPass123
- 系统运行正常，登录页面可访问

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 打开登录页面 | 显示登录表单，含用户名和密码输入框 |
| 2 | 输入用户名 testuser@example.com | 输入框显示输入内容 |
| 3 | 输入密码 ValidPass123 | 密码框显示掩码内容 |
| 4 | 点击"登录"按钮 | 跳转到首页，显示用户名 |

### 附加验证点

- 登录成功后数据库中记录最后登录时间
- 登录成功后生成有效的访问令牌（Access Token）

### 后置清理

- 退出登录
- 清除浏览器 Cookie

## 缺陷关联

测试用例执行失败时，创建缺陷并关联本用例编号。缺陷格式按 [缺陷管理规程](defect-management-procedure.md)。
