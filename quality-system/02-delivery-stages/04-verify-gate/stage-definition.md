# 04-verify-gate：验证与准入

## 1. 环节定位

验证与准入环节位于集成构建之后、发布部署之前，负责判断版本候选是否具备发布条件。

它不是简单的“测试阶段”，而是质量门禁环节。

它解决的问题是：
这个版本能不能发布？风险是否可接受？证据是否充分？

对应传统软件工程中的：
- 系统测试
- 集成测试
- 回归测试
- 验收测试
- 安全测试
- 性能测试
- 质量准入

## 2. 环节目标

- 确认测试范围。
- 验证本次变更是否满足需求和验收标准。
- 验证本次变更是否破坏已有能力。
- 验证关键业务链路是否可用。
- 验证性能、安全、兼容性等非功能要求。
- 对缺陷进行分级和准入判断。
- 形成明确的质量门禁结论。

## 3. 进入条件

- 持续集成流水线成功，制品已生成并部署到测试/验证环境。
- 测试策略与计划已制定（如适用）。

## 4. 退出条件

- 测试执行完成，验收标准验证通过。
- 遗留缺陷符合发布准入标准（无致命/严重未修复缺陷）。
- 质量门禁判断为“通过”，具备发布候选资格。

## 5. 必须规程

- 测试范围确认
- 集成测试
- 回归测试
- E2E 测试
- 非功能测试
- 安全验证
- 缺陷分级
- 质量门禁判断

关键说明：集成测试、E2E 测试虽然可能写在代码仓库中，但它们的质量体系归属建议放在验证与准入环节。原因是：它们主要用于判断版本候选是否可以发布，而不是判断单个开发任务是否完成。

## 6. 主要证据

- 测试计划与用例清单
- 测试执行报告（自动化测试报告与手工测试报告）
- 缺陷清单与处理状态
- 性能测试报告（如涉及）
- 安全测试报告（如涉及）
- 质量门禁评审记录/报告

## 7. 责任角色

- 测试工程师 / 质量保证工程师
- 研发工程师
- 项目经理 / 产品经理

## 8. 流水线验证点

- 自动化 API 集成测试
- 自动化 E2E UI 测试
- 自动化性能基准测试
- 动态应用安全测试（DAST）

## 9. 横切能力关联

- 追溯：测试用例与需求、缺陷的追溯。
- 审批豁免：质量门禁未满足时的特批/豁免流程。
- 安全：渗透测试、安全验证。

## 10. 指标预留

- 缺陷发现率
- 自动化测试覆盖率
- 遗留缺陷密度
- 测试周期时长
