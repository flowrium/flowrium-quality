# 03-integrate-build：集成与构建

## 1. 环节定位

集成与构建环节负责将代码变更安全地合并到共享分支，并通过持续集成生成可追溯、可验证、可部署的构建制品。

它解决的问题是：
代码能不能合进去？系统能不能构建出来？构建出来的东西能不能追溯？

对应传统软件工程中的：
- 代码集成
- 构建
- 打包
- 配置管理
- 制品管理

## 2. 环节目标

- 确保代码合并前满足准入条件。
- 确保代码可以被持续集成。
- 确保静态分析、规则检查能够尽早发现问题。
- 确保构建过程可重复。
- 确保制品有明确版本标识。
- 确保制品、源码、依赖、构建记录可追溯。

## 3. 进入条件

- 代码已完成开发、代码评审和本地测试。
- 触发代码合并请求（Merge Request / Pull Request）或提交到目标分支。

## 4. 退出条件

- 代码成功合并到目标分支。
- 持续集成流水线执行通过。
- 生成具有明确版本号和可追溯标识的制品（Artifact）。
- 制品已归档至制品库。

## 5. 必须规程

- 合并准入检查
- 持续集成
- 静态分析
- 构建与打包
- 制品版本标识
- 制品归档

关键说明：静态扫描建议放在这个环节，因为它通常发生在构建或合并流水线中，属于持续集成质量控制。如果静态扫描涉及安全规则，则同时与 03-cross-cutting/01-security 及 04-pipeline-verification/checks/vp-sec-security-gate.md 关联。

## 6. 主要证据

- 代码合并记录
- 流水线执行日志与结果
- 静态扫描报告
- 单元测试执行报告（在流水线中生成的报告）
- 构建生成的制品记录（版本号、哈希值等）

## 7. 责任角色

- 研发工程师
- 配置管理员 / DevOps 工程师
- 技术Leader

## 8. 流水线验证点

- 编译构建验证
- 流水线单元测试执行
- 代码覆盖率门禁
- 静态代码分析检查（如 SonarQube）
- 开源依赖安全扫描预检查

## 9. 横切能力关联

- 配置管理：分支策略、版本命名规范。
- 安全：静态应用安全测试（SAST）、软件成分分析（SCA）。
- 追溯：代码Commit与制品、工单的关联。

## 10. 指标预留

- 构建成功率
- 构建时长
- 静态扫描缺陷密度
- 流水线阻断次数
