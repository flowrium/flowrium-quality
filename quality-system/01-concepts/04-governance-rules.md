# 治理规则

## 1. 治理规则定位

治理规则用于保证质量体系能够被执行、维护和持续改进。

如果没有治理规则，质量体系容易变成静态文档；如果治理过重，又会阻碍产品交付。

本体系治理原则是：

> 必要约束、风险分级、证据留存、允许裁剪、受控豁免、持续改进。

## 2. 文档治理

1. 所有质量体系文档应纳入版本管理。
2. 文档修改应通过 Pull Request 或同等评审机制。
3. 关键文档修改应说明变更原因。
4. 废弃文档应明确标记或归档。
5. 文档之间应避免重复定义和冲突定义。

## 3. 目录治理

1. 主目录结构应保持稳定。
2. 新增一级目录必须说明理由。
3. 规程应放在对应交付环节下。
4. 横切能力不得随意放入某个单一环节。
5. 指标、验证点、标准映射应分别维护，避免混写。

## 4. 规程治理

1. 每个规程必须有明确目的。
2. 每个规程必须说明触发条件。
3. 每个规程必须说明输入和输出。
4. 每个规程必须说明责任角色。
5. 每个规程必须说明证据要求。
6. 可以被流水线验证的规程，应关联验证点。

## 5. 流水线验证治理

1. 流水线验证点应有唯一编号。
2. 验证点应说明触发时机。
3. 验证点应说明通过条件。
4. 验证点应说明失败策略。
5. 验证点应产出可追溯证据。
6. 阻断类验证点不得被项目随意绕过。

## 6. 证据治理

1. 关键质量活动必须留下证据。
2. 证据应能够关联到需求、代码、测试、制品或发布。
3. 证据应有保留期限。
4. 证据应便于审计和复盘。
5. 自动化证据优先于人工口头结论。

## 7. 裁剪治理

1. 项目可以根据风险和复杂度裁剪规程。
2. 裁剪不得删除关键质量责任。
3. 裁剪不得删除关键风险控制。
4. 高风险项目不得使用最低规程集。
5. 裁剪结果应有记录。

## 8. 评审治理

1. 质量体系应定期评审。
2. 重大质量事故后应触发专项评审。
3. 新技术或新研发模式引入后应评估体系适配性。
4. 无效规程应被简化或废弃。
5. 有效实践应沉淀为标准规程。

## 9. 责任治理

1. 每个质量活动必须明确主责角色。
2. 每个验证点必须明确维护责任。
3. 每个豁免必须明确批准责任。
4. 每个改进项必须明确关闭责任。
5. 质量负责人负责体系一致性和持续演进。
