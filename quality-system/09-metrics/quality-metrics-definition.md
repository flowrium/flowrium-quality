# 质量度量指标定义

## 概述

本文件定义质量管理体系各环节的量化指标和检验标准。指标按 L4 度量层组织，覆盖全局指标和各环节指标。

## 指标分级

| 级别 | 说明 | 使用场景 |
|------|------|---------|
| 全局指标 | 反映整体质量水平 | 管理评审、对外报告 |
| 环节指标 | 反映特定流程环节质量 | 日常监控、过程改进 |

## 全局质量指标

| 指标 | 英文 | 定义 | 计算方式 | 目标值 | 采集频率 |
|------|------|------|---------|--------|---------|
| 生产缺陷密度 | Production Defect Density | 每千行代码的生产缺陷数 | 生产缺陷数 / 代码千行数 | ≤ 2/KLOC | 月度 |
| 发布返工率 | Release Rework Rate | 发布后需热修或回滚的占比 | 热修/回滚次数 / 总发布次数 | ≤ 5% | 按发布 |
| 客户满意度 | Customer Satisfaction | 用户调查评分 | 调查得分 / 满分 | ≥ 85% | 季度 |

## 各环节指标

### 需求定义

| 指标 | 英文 | 定义 | 计算方式 | 目标值 | 采集频率 |
|------|------|------|---------|--------|---------|
| 需求变更率 | Requirement Change Rate | 开发阶段需求变更占比 | 变更需求数 / 总需求数 | ≤ 15% | 按迭代 |
| 需求评审通过率 | Requirement Review Pass Rate | 一次评审通过占比 | 一次通过数 / 评审总数 | ≥ 80% | 按迭代 |

### 方案设计

| 指标 | 英文 | 定义 | 计算方式 | 目标值 | 采集频率 |
|------|------|------|---------|--------|---------|
| 设计评审通过率 | Design Review Pass Rate | 一次评审通过占比 | 一次通过数 / 评审总数 | ≥ 80% | 按迭代 |
| 架构违规数 | Architecture Violation Count | 代码中违反架构约束的数量 | 架构测试/扫描结果 | = 0 | 持续 |

### 开发构建

| 指标 | 英文 | 定义 | 计算方式 | 目标值 | 采集频率 |
|------|------|------|---------|--------|---------|
| 单元测试覆盖率 | Unit Test Coverage | 行覆盖率 | 已覆盖行 / 总行数 | ≥ 80% | 每次构建 |
| 核心领域覆盖率 | Core Domain Coverage | 核心领域逻辑行覆盖率 | 已覆盖行 / 核心领域总行数 | ≥ 95% | 每次构建 |
| 代码审查覆盖率 | Code Review Coverage | 经审查的代码占比 | 已审查变更集 / 总变更集 | 100% | 每次合并 |
| 静态分析高危问题 | SAST Critical Issues | 新增高危问题数 | SAST 扫描结果 | = 0 | 每次构建 |
| 构建失败率 | Build Failure Rate | CI 构建失败占比 | 失败构建数 / 总构建数 | ≤ 5% | 月度 |

### 质量确认

| 指标 | 英文 | 定义 | 计算方式 | 目标值 | 采集频率 |
|------|------|------|---------|--------|---------|
| 测试用例通过率 | Test Case Pass Rate | 执行通过 / 总用例 | 通过数 / 执行数 | ≥ 98% | 每次测试 |
| 严重缺陷清零 | Zero Critical Defects | 发布时 P0/P1 缺陷数 | 缺陷系统统计 | = 0 | 发布前 |
| 缺陷修复时效 | Defect Fix Time | 各等级修复时间达标率 | 达标数 / 总缺陷数 | ≥ 95% | 月度 |
| 缺陷逃逸率 | Defect Escape Rate | 生产缺陷占总缺陷比 | 生产缺陷 / (测试+生产缺陷) | ≤ 10% | 月度 |
| 自动化测试占比 | Test Automation Rate | 自动化 / 总用例 | 自动化数 / 总用例数 | ≥ 60% | 月度 |
| 安全漏洞修复时效 | Security Vuln Fix Time | 高危/中危修复时间达标率 | 达标数 / 总漏洞数 | 100% | 按漏洞 |

### 发布交付

| 指标 | 英文 | 定义 | 计算方式 | 目标值 | 采集频率 |
|------|------|------|---------|--------|---------|
| 发布成功率 | Release Success Rate | 一次发布成功占比 | 成功数 / 总发布数 | ≥ 95% | 按发布 |
| 发布耗时 | Release Duration | 从触发到上线的时长 | 发布系统记录 | ≤ 30min | 按发布 |

### 运维保障

| 指标 | 英文 | 定义 | 计算方式 | 目标值 | 采集频率 |
|------|------|------|---------|--------|---------|
| 系统可用性 | System Availability | SLA 达标率 | 正常运行时间 / 总时间 | ≥ 99.9% | 月度 |
| 告警响应时效 | Alert Response Time | 告警到响应的时间 | P0 ≤ 5min, P1 ≤ 15min | 达标率 ≥ 95% | 月度 |
| 事件恢复时效 | Mean Time To Recovery | 平均恢复时间 | 总恢复时间 / 事件数 | ≤ 2h | 月度 |

## 修复时效标准

### 缺陷修复时效

| 等级 | 目标 | 超时处理 |
|------|------|---------|
| P0 | ≤ 4 小时 | 立即升级 |
| P1 | ≤ 24 小时 | 每日跟踪 |
| P2 | ≤ 72 小时 | 迭代内跟踪 |
| P3 | 下个版本 | 计划排期 |

### 安全漏洞修复时效

| 等级 | CVSS 评分 | 目标 |
|------|----------|------|
| 高危 | ≥ 7.0 | ≤ 24 小时 |
| 中危 | 4.0 - 6.9 | ≤ 7 天 |
| 低危 | < 4.0 | ≤ 30 天 |

## 数据采集与报告

| 报告类型 | 频率 | 内容 | 受众 |
|---------|------|------|------|
| 质量日报 | 每日 | 构建状态、测试结果、新增缺陷 | 开发团队 |
| 质量周报 | 每周 | 缺陷趋势、测试进度、风险项 | 技术负责人 |
| 质量月报 | 每月 | 全局指标、各环节指标、改进项 | 管理层 |
| 管理评审报告 | 季度 | 体系运行有效性、改进成效 | 最高管理者 |

## 指标改进

指标目标值不是静态的，应根据以下情况调整：

- 连续 3 个月达标 → 考虑提高目标值
- 连续 2 个月未达标 → 分析原因、制定改进计划
- 体系重大变更后 → 重新校准目标值
